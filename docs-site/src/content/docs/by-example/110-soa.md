`#soa(N)` on a struct declaration lays it out as **one array per field** rather than one array of
structs. `Entities :: struct #soa(4) { x: s64; hp: u8; }` allocates a `[4]s64` for `x` and a `[4]u8` for
`hp`, and the sugar `e[i].x` rewrites at compile time to `e.x[i]` — the field's own array, indexed
(ADR-0147). No engine had to learn a new instruction for this: it is entirely a change to how a struct's
fields resolve before layout runs, so the three-way differential exists to confirm that a sema-only
feature really did produce identical bytes in all three engines.

## Declaring, writing, and reading through both spellings

```jr
#import "Basic";

COUNT :: 4;

Entities :: struct #soa(COUNT) {
    x: s64;
    hp: u8;
}

main :: () {
    e: Entities;

    // The sugar as a *write* target, which is the half a read-only test would miss: the place is
    // built the same way, so a rewrite that only fired on reads would produce a program that
    // compiled and stored nothing where it was told to.
    i := 0;
    while i < COUNT {
        e[i].x = i * 10;
        e[i].hp = cast(u8, i);
        i = i + 1;
    }

    total := size_of(Entities);
    j := 0;
    while j < COUNT {
        total = total + e[j].x + cast(s64, e[j].hp);
        j = j + 1;
    }

    // **The two spellings must agree**, which is the claim that makes the sugar sugar: a reader who
    // does not know about `e[i].x` can still read every program, because the field genuinely is an
    // array and `e.x[i]` is an ordinary index. If these ever differ, one of them is a wrong address.
    if e[2].x == e.x[2] {
        total = total + 20;
    }

    exit(total);
}
```

`COUNT` must be a named constant bound to an integer literal, not an expression like `COUNT * 2` — the
same rule an ordinary array length follows, and for the same reason: a struct's fields are laid out
*with* its declaration, before the compile-time evaluator has anything to run. `size_of(Entities)`
folds from that layout exactly as it would for any other struct: four `s64`s (32 bytes) plus four `u8`s
(4 bytes) end at 36, and the struct's own alignment of 8 rounds that up to 40. The exit status is **126**
— a checksum of the size, the `x` values (`0+10+20+30 = 60`), the `hp` values (`0+1+2+3 = 6`), and the
one bit that only sets when the two spellings genuinely agree.

## Why `e[i]` on its own has no type

```jr
// EXPECT: E0284 — an `#soa` struct indexed as something other than a field receiver (ADR-0147 §2)
Entities :: struct #soa(4) {
    x: s64;
    hp: u8;
}

main :: () {
    e: Entities;
    e.x[0] = 1;
    one := e[0];
}
```

`e[0]` alone is <span class="jairs-status refused">refused</span> with E0284, by design rather than as a
missed case. The fields of an `#soa` struct live in **separate arrays**, so there is no single
contiguous element to hand back for a bare index — the alternative is Jai's synthesised
struct-of-pointers, a real design with its own type that exists only as an intermediate and needs
pointers into N arrays kept consistent, and refusing here leaves that available rather than foreclosing
it. `e.x[0]` and `e[0].x` both work; `e[0]` by itself does not, and the diagnostic names both working
spellings rather than the general "cannot index a value of type …" a reader would otherwise get, because
that message would be true and unhelpful to someone who just wrote `#soa` expecting exactly this to
work.

The same refusal also covers a `using` field inside an `#soa` struct — `using` promotes a field for
lookup, and under `#soa` each promoted name would itself be an array with no spelling for the index — and
a count that is not a usable positive array length, including one needing evaluation, for the same
layout-ordering reason `COUNT` above must be a plain literal-bound constant.

## Why a game reaches for this

A `#soa` struct is the shape an entity system wants once it starts iterating one field across every
entity: updating every `x` in a physics pass touches one contiguous `[N]s64` rather than striding through
an array of structs and skipping past `hp`, `vx`, `vy` and everything else on every entity. `e[i].x` reads
exactly like ordinary struct field access at the call site, so a loop written against an ordinary
`[N]Entity` needs no rewriting to become SoA — only the declaration's `#soa(N)` and the array size change.
