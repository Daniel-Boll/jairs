# ADR-0156: `JSON` — a flat node store, and the first module that needs both allocators

- **Status:** Accepted
- **Date:** 2026-09-02
- **Deciders:** dboll
- **PLAN §8.3 item 4 of W7's nine modules**, which §8.3 called "the most valuable module for proving the
  language, because it exercises tagged unions, containers and strings together".
- No design fork was put to the decider; the recommended approach was taken and the rejected
  alternatives are recorded below, per the session directive.

## Context

`JSON` was scheduled fourth because it was blocked on the error model, and `#must` (ADR-0151) unblocked it.
It is the first module in this library that is not a *utility*: it has a data model, a grammar, a failure
mode, and two kinds of allocation. That makes it the first real test of whether the language's pieces
compose, and the answer is yes — with two things recorded rather than papered over (§4, §5).

The module exercises, in one file: `#must` (ADR-0151), multiple return values (ADR-0052), `[..]T` as a node
store (ADR-0136), `view` over it because a `[..]T` cannot be indexed (ADR-0109), `enum` for the kind, the
context allocator (ADR-0062), temporary storage (ADR-0065), and a float crossing the `#foreign` boundary
(ADR-0114).

## Decision

### 1. A flat node store with index handles, not a recursive value type

A JSON value is recursive, so the obvious shape — a `variant` whose cases include a list of itself — needs
indirection. The choice is a pointer per node or an **index** per node, and this takes the index: one
`[..]Json_Node`, a value is an `s64` into it, and children are a `first`/`next` sibling chain.

Three reasons, in the order they mattered. **Freeing is one call**: `free_document` releases the array and
every string in it, where a pointer tree needs a recursive walk that has to be right on the error path too.
**A handle is copyable and comparable**: an `s64` can be stored, compared and passed with no ownership
question, and `NONE` is a real absent value rather than a null nobody checked. And **it is what fast parsers
do** — a tape is cache-friendly in the order a parse produces and a walk consumes — which is third rather
than first because this project does not measure the programs it compiles (ADR-0146 §4).

**Rejected: a `variant` of cases with `*Json` children**, the textbook DOM. It reads better at the type
level and is worse everywhere else: a recursive free, an ownership question at every field, and a partial
tree to unwind when a parse fails halfway. Note the irony worth naming — §8.3 scheduled this module partly
to exercise `variant`, and writing it found that a *flat* store is the better shape, so the tagged union
this module actually uses is the `Json_Kind` enum plus checked accessors. `variant` would refuse a
wrong-case read, which is exactly right, but the parser fills fields in an order the tag does not yet know,
and a node is the same size either way once a `string` and a `float64` are in it.

**Rejected: a `Map` per object.** `Map` is `Map(s64, s64)` today and cannot key on a string at all, and it
would be slower than a linear scan for the three-to-five keys a real object has. Members are a chain,
scanned in order, which also **preserves source order** — something a hash map destroys and a
diff-minded or round-tripping caller needs.

**`NONE` is `-1`, not `0`**, because `0` is the root's own index in every non-empty document and a sentinel
that collides with a real value is the bug the constant exists to prevent.

### 2. The extent is JSON's grammar; the value is `strtod`

A JSON number is a decimal in the source and a `float64` in the model, and converting **exactly** is a hard
problem — the argument `Math` makes about `sqrt` (ADR-0112) applies with more force, because a wrong last
bit in a parsed number is a wrong *answer* rather than a wrong approximation. So the platform's
correctly-rounded `strtod` does the conversion, reachable because ADR-0114 let a float cross the `#foreign`
boundary.

But `strtod` alone would accept `0x1p3`, `inf`, `nan` and a leading `+`, none of which are JSON. So the
**scanner says what a number is** and **libc says what it equals**. That split is the decision, and it is
also why the scanner cannot be skipped: it is the only thing that rejects what C accepts.

**Integers are converted in Jairs**, not from the float, and that is not an inconsistency. An integer's
conversion is exact arithmetic with no rounding question, `s64` is what a caller indexing or counting wants,
and going through `float64` loses precision above 2^53 — `9007199254740993` would come back as
`…992`, a silently wrong answer. So a number carries both, with `is_integer_at` to ask which is meaningful,
and overflow past `s64` leaves the flag false so the float remains the only answer, which is honest because
the exact integer genuinely does not fit.

`valid/127` pins exactly that case, because it is the one a reviewer would otherwise have to take on trust.

### 3. Accessors answer questions; they do not assert facts

`kind_of` of an out-of-range index is `NULL_`; `number_of` of a string is `0.0`; `string_of` of a number is
`""`. So `string_of(doc, member(doc, obj, "missing"))` is the empty string rather than a trap.

That is the opposite of what a `variant` would do, and deliberate: a caller inspecting **untrusted** JSON is
asking whether something is there, not asserting that it is. A trap would make every read a two-step
(`has_member` then read) and would turn a malformed document into a crashed program — which is precisely the
failure mode a JSON parser exists to prevent. A caller who wants the assertion compares against `NONE`
first, which is one comparison and reads as the assertion it is.

**Strings are borrowed, not copied.** The document owns them; a caller who needs one to outlive the document
`concat`s or `substring`s it. Returning a copy would make every read allocate and every caller free, which
is the wrong default for an inspector.

**Refusals are the specification.** Each of these is accepted by some real parser, which is why `valid/127`
checks it: a trailing comma (JavaScript takes it), a leading zero (`strtol` takes it), trailing content (a
truncated stream looks like a valid prefix), a lone surrogate (many parsers substitute U+FFFD, turning
malformed input into a valid document that says something the source did not), and `1.` (C takes it).

A `\uXXXX` escape becomes **UTF-8**, and a surrogate **pair** is recombined before encoding — the one place
JSON's escape syntax needs two escapes for one code point, and the place a parser that handles each `\uXXXX`
independently emits two broken three-byte sequences instead of one four-byte one.

**No duplicate-key policy.** Both copies are kept in source order and `member` finds the first, because JSON
itself does not say what a duplicate means and inventing a rule here would be inventing semantics.

**No depth limit** on the recursive descent. The limit that matters is the caller's stack, a cap would be an
arbitrary number in a library, and a caller parsing untrusted input has to bound the *input size* anyway,
which bounds the depth. Recorded because the absence looks like an oversight otherwise.

**No serialisation**, and this is the one deliberate hole. Writing a document out needs a `float64` rendered
as the shortest decimal that round-trips — a correct `dtoa` — and an approximate one would emit numbers this
module could not read back, which is worse than emitting none. `String`'s allocating half is ready for the
rest of it, so this is a wave's work behind a single missing piece, named rather than half-built.

### 4. `String.adopt` — the library's allocator seam, made visible

Parsed strings are unescaped into a buffer the parser sizes itself, so the result exists as *bytes* before it
exists as a `string`. `String.make_string` did that and was module-private, on the stated ground that "a
caller has no business constructing a `string` from raw parts" — which was right while every caller built a
string from other strings.

It is now exported as **`adopt(data, count)`**, named for the contract: it takes over an allocation, where a
`make`/`from_bytes` would suggest a copy. **Rejected: JSON assigning the fields itself** — the same five
lines with no shared contract to read. **Rejected: `String` growing an `unescape`**, which belongs to JSON's
grammar rather than to strings.

And the buffer comes from **`context.allocator`, not `malloc`**, because `String.free_string` releases
through `context.allocator_free`. Allocating with `malloc` would pair a libc allocation with a context free
— invisible while the installed allocator *is* libc, and corruption the moment a caller installs an arena.
That is a bug this wave wrote and caught, and it exposes a real **seam in the library**: `List` and `Map`
allocate with `malloc`, `String` through the context, and `JSON` is the first module that needs both. The
node store follows the containers and the strings follow `String`, with the split named in the module docs.
Unifying it is a decision about every container at once and is not this wave's.

### 5. A field of a call's result does not lower

`mk().count`, where `mk` returns a `string`, is refused as "a memory reference has no place" — E0245, so a
legal program silently does not lower. MIR needs a *place* to read a field from and a call produces a
*value*; the fix is to materialise the result into a temporary slot, the same move ADR-0076 §1 makes for an
`Any` and ADR-0139 §2 for a variadic pack, which is why it is small rather than structural.

Recorded in PLAN's known-defects list rather than fixed here, because it is a MIR change and this is a
library wave. The workaround is a named local, which `valid/127` uses in four places. It is the **third**
capability gap a library has surfaced rather than a compiler test — ADR-0104's two leaked internal errors
were the first two — which is the argument for a standard library written in the language, paying out again.

## Consequences

- **`modules/JSON`** is new. `modules/String` exports `adopt`.
- **`valid/127`** is twenty independent bits rather than a sum, so one failure cannot hide inside another's
  success: structure, typed reads, all eight escapes, four UTF-8 widths including a surrogate pair, three
  number cases including 2^53 + 1 exactly, five refusals, and both empty containers. All three engines print
  1048575 and exit 148.
- **W7 is four of nine.** `File`, `File_Utilities`, `Process`, `Socket` remain, all four unblocked by the
  error model; `Compiler` moved to W6 and shipped there; `Thread` is W11.
