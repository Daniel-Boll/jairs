# ADR-0080: `#code { … }` is unquoted source that splices, and it is sugar over `#insert`

- **Status:** Accepted
- **Date:** 2026-08-03
- **Deciders:** dboll
- **W4 sub-wave 10, part 2.** ADR-0072 §4 deferred "`#code` and the `Code` type" and asked the right first
  question: does a `Code` value exist at run time? Probing before writing this found that the *feature* is
  narrower than the name suggests — §0 — so this ADR delivers the ergonomic half and says plainly that it
  is sugar.

## Context

### 0. What running found, and what it narrows

Two facts, each checked:

- **`#insert` of a named constant already works.** `CODE :: "n := 7;";` then `#insert CODE;` splices and
  the program exits 7. ADR-0073 delivered that; the sub-wave list still spoke as though a `Code` value were
  needed to reach it.
- **A malformed operand already reports well.** `#insert "n := ;";` gives
  `error[E0263]: inserted code does not parse: expected an expression after ':='`, with
  `= in inserted code, at offset 5` and the text echoed. So the diagnostic quality a quote-site check would
  buy is largely already there.

What is left that a string genuinely does *not* give:

- **Quoting and escaping.** Inserted code that itself contains a string, or a nested insert, has to escape.
  ADR-0072 §5 noted escaping doubles the text per level — that is what *bounds* a written nest, but it also
  makes anything beyond a line unpleasant to write.
- **The check's *position*.** A string is opaque to the parser at the write site; its fault is reported at
  the directive with an offset into the text. Unquoted source is parsed where it is written.

That is a real ergonomic gain and it is *not* a new capability. This ADR is explicit about that, because
"`#code` and the `Code` type" reads like a syntax-tree value and shipping sugar under that name would be
the kind of overclaim the README's status section exists to prevent.

### The CST is lossless, which decides the implementation

`jr-syntax` keeps every token and trivium, so a node's original source text is recoverable
(`SyntaxNode::text()`). A `#code { … }` body can therefore be *parsed as an ordinary block* — getting real
diagnostics at real positions — and then handed to the `#insert` machinery **as its own source text**. No
new representation, no new pool variant, no engine change.

## Decision

### 1. `#code { … }` parses a braced body and splices its text, like `#insert`

```
#code {
    n := 7;
}
print_int(n);      // 7 — the same enclosing scope an `#insert` splices into
```

The body is parsed as a **block** so it is checked at the write site, and its statements are then lowered
through `#insert`'s path: into the **enclosing** scope, not a nested one, which is ADR-0072 §1's rule and
the reason `n` is visible on the next line.

**Braces are required**, unlike `#insert`'s single expression. A braceless `#code n := 7;` would have to
decide where the quoted region ends, and "until the next `;`" cannot express two statements — the same
argument ADR-0063 made for `push_context` needing a block rather than the two-shape `ControlBody`.

### 2. It lowers to `Stmt::Insert`, and that is the whole implementation

`#code { … }` produces the same `Stmt::Insert` a literal `#insert "…"` does, with the body's recovered
source text as the inserted text. Consequences worth naming:

- **Every `#insert` guarantee applies unchanged**: the depth bound (E0264), the refusal of a pending
  insert by `jr-mir`'s `scan`, the span rule that attributes synthesized nodes to the directive.
- **The spans are the directive's**, not the body's — even though the body *is* real source in this file.
  That is a deliberate cost: reusing `expand_insert_text` means the text is re-parsed as inserted text, and
  ADR-0072 §2 established that inserted spans must point at the directive because `jr-diag` clamps an
  out-of-range offset rather than rejecting it. Attributing them to the body's real range would be *better*
  and is not free — it needs a span-offset mechanism the insert path does not have. Recorded here rather
  than discovered: a diagnostic inside a `#code` body points at the `#code`, and §4 owes the fix.

### 3. No `Code` *type*, and no value

There is no `Code` type, no `Item::CodeValue`, and `#code` is not an expression — it is a statement.
ADR-0072 §4's question ("does it exist at run time?") is answered "it does not exist at all": a quoted
syntax tree as a *value* would be useful only if something could **inspect or transform** it, and nothing in
W4 asks for that. A value that can only be spliced is what a `string` already is.

**Rejected: `Item::CodeValue` holding a CST or HIR fragment.** It is the feature the name implies, and it is
cost without a payer: the pool would gain a variant that is comptime-only (like `Item::TypeType`, so it
needs ADR-0071 §3's whole refusal apparatus to stop it reaching a runtime slot), both engines would need to
decide what an unrepresentable value means, and the observable behaviour would be identical to splicing text
until a macro exists that reads its argument. When one does, it supersedes this ADR with the real
representation — and it will be a better decision for having a working splice to compare against.

**Rejected: `#code` as an expression yielding a string.** `s := #code { n := 1; };` would make it
`stringify`, which is a different feature with a different name, and it would invite `s + s` — string
concatenation of source — which nothing checks.

### 4. What is deliberately absent

- **Spans into the body's real source** (§2). A diagnostic inside a `#code` body points at the `#code`
  directive. The fix is a span-offset mechanism for inserted text, which serves `#insert` equally and is
  owed to both.
- **A `Code` value, type, or any inspection** (§3).
- **`#code` at file scope**, for ADR-0072 §5's reason unchanged: it would change the item tree.

## Consequences

- **The last `#insert`-family item ships as sugar, honestly labelled.** PLAN §2.1 listed "`#insert` and the
  `Code` type" as one sub-wave; what exists after this is `#insert` with three operand forms and a braced
  spelling. The `Code` *type* is not deferred-with-a-plan, it is **declined** until something needs to
  inspect a tree.
- **No new diagnostic code.** Every refusal is one `#insert` already had: a body that does not parse is
  E0263, too deep a nest is E0264.
- **A span-quality debt is now explicit** (§2, §4) and shared with `#insert` rather than unique to `#code`.
